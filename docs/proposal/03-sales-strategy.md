# 営業戦略（社内限定）

## 1. 「デジモンを開発した会社」の整理

ここを間違えるとアポが取れないので、先に事実を押さえます。

| 会社 | 役割 | この提案での位置づけ |
|---|---|---|
| **株式会社ウィズ（WiZ）** | 1996年に『デジタルモンスター』を**企画・原案** | 原点の発明者。ただし玩具企画が主軸で、PCアプリ事業の意思決定者ではない可能性 |
| **株式会社バンダイ** | 1997年6月26日に**発売**。IPの権利主体 | **ライセンス許諾の最終判断者。本命** |
| **バンダイナムコエンターテインメント** | ゲーム化・デジタル事業 | デジタル製品としての事業パートナー候補 |
| **東映アニメーション株式会社** | TVアニメ『デジモンアドベンチャー』以降の**アニメ制作** | 「アニメーション会社」に当たるのはここ。映像IPの窓口 |

> 補足: 権利表記の「本郷あきよし」はウィズとバンダイの共同ペンネーム（ハウスネーム）です。
> つまり**原作権はウィズ＋バンダイに分散している**前提で話を進めてください。

### 推奨アプローチ順

```
1st  バンダイ（または バンダイナムコエンターテインメント）
     → ライセンスと事業化の意思決定ができる。ここが本丸

2nd  東映アニメーション
     → 「アニメ会社に売りたい」という要望に最も合致。
        映像IP側からの切り口。新規事業/ライセンス部門へ

3rd  ウィズ
     → 原点のリスペクトとして接触する価値はあるが、
        単独では事業化の決裁が降りにくい
```

### ただし ── 最初の1社をデジモンにする是非

**リスク**: 大手IPは初回提案で必ず「実績は？」と聞きます。
そして**一度断られたIPには2〜3年入り直せません。**

ただし今回は「御社が作って売ってください」という立ち位置なので、
求められる実績は**「運営実績」ではなく「実装できる証明」**です。
**自社キャラクター「ロウ」の実機がひとつあれば、その条件は満たせます。**

**推奨する順番**:

| 順 | ターゲット | 目的 | 状態 |
|---|---|---|---|
| 0 | **ロウ（自社IP）で参考機を完成させる** | 実装できる証明を作る | 【要確認: 現状】 |
| 1 | 中堅アニメ制作会社・ゲーム会社・VTuber事務所 | 1社目の導入実績を作る（任意） | 未着手 |
| 2 | **デジモン（バンダイ／東映アニメーション）** | 本命 | 未着手 |

> **Step 1 は飛ばしても構いません。** ただし **Step 0 は絶対に飛ばさないでください。**
> 資料だけの提案は、この規模の会社ではまず通りません。
> 逆に言えば、ロウが動いていれば、最初からデジモンに当てても勝負になります。

## 2. 当てるべき部署・役職

| 会社タイプ | 部署 | 役職 |
|---|---|---|
| IPホルダー（バンダイ等） | ライセンス事業部 / 新規事業開発 / デジタル事業 | 部長〜課長クラス |
| アニメ制作（東映アニメーション等） | 事業推進 / ライセンス / 新規事業 / DX推進 | 同上 |
| ゲーム会社 | 新規事業 / R&D / IP戦略 | 同上 |

**避けるべき窓口**: 総合お問い合わせフォーム（ほぼ届かない）、制作部門（決裁権なし）

**有効な接点**:
1. 展示会・カンファレンス（AnimeJapan、東京ゲームショウ、Licensing Japan、AI系イベント）
2. 共通の知人・投資家・取引先からの紹介
3. LinkedIn / X での担当者への直接接触
4. プレスリリースで話題を作り、向こうから来てもらう

## 4. 初回商談トークスクリプト（30分）

> **軸**: 「IPを貸してください」ではなく「**御社が作って、御社が売ってください**」。
> これは相手の警戒を一段下げると同時に、話の格を「下請けの売り込み」から
> 「事業構想の持ち込み」に上げます。絶対にブレさせないこと。

### 掴み（2分）
> 「**デジモンに、時代が追いついたと思っています。**
>
> 1997年のあの製品が提示していたのは、"デバイスの中に自分だけの存在が住んでいて、
> 世話をすると育って、姿が変わる"という構想でした。
> それは玩具の仕様ではなく、**いま世界中の企業がAIエージェントという名前で
> 追いかけているもの**そのものです。
>
> 御社は27年前に答えを出していた。足りなかったのは技術だけでした。
> それが、この2〜3年で揃いました。」

### 5つのピース（3分）
> 「当時なかったものが5つあります。
> **器**は手のひらの単色液晶から、1日8時間目の前にあるPCになりました。
> **対話**はボタン3つから自然言語になりました。
> **知能**は、決められた反応しかなかったものが、その子らしく応えられるようになりました。
> **育成の材料**は、ゲーム内の操作回数しかなかったものが、
> ユーザーの実生活──予定、達成、習慣──が使えるようになりました。
> **つながり**は、端子を繋いだ一瞬の通信から、常時オンラインになりました。
>
> 5つ揃ったのは、本当に最近です。だから今日お伺いしました。」

### デモ（10分）
> 説明より先に動かす。当社キャラ「ロウ」の実機を見せる。
> **喋らせすぎない。黙っている時間の自然さを見せる。**

### 立ち位置の表明（5分）★ここが本提案の勝負どころ
> 「ここで正直に申し上げます。
> **私どもは、御社のIPをお借りしたいのではありません。**
> **御社が開発して、御社が売ってください、というご提案です。**
>
> 理由は3つあります。
>
> ひとつ、**私どもにはIPがありません。** この構想はIPがないと成立しません。
> ゼロから作ったキャラクターでは"初めて会った日からの積み重ね"しか生まれない。
> 御社のIPには、ユーザーが子どもの頃から積み上げた27年分の関係が既にあります。
> これは後から作れません。
>
> ふたつ、**御社にとって"貸す"形は損です。** 私どもが開発・運営すれば、
> 御社に残るのはロイヤリティだけです。開発ノウハウも、ユーザーとの直接の関係も、
> 行動データも、当社側に溜まってしまう。御社が作れば、全部が御社の資産になります。
>
> みっつ、**IPの安全は、内製がいちばん確実です。**
> "キャラクターを壊されるのでは"というご懸念への最も確実な答えは、
> 外部に厳しい契約を課すことではなく、御社が手綱を握ることです。」

### 何を売るのか（5分）
> 「では何をお売りするのか。**中身と、作り方です。**
>
> 中身は Addness というAI行動支援OSです。
> 見た目は御社が作れます。当然です。
> ですが"人の行動を実際に変える"部分は、キャラクター制作とは全く別の技術です。
> 雑談できるAIは誰でも作れますが、雑談では生活は変わらない。
> 生活が変わらなければ進化の材料が生まれない。
> **材料が生まれなければ、この構想は成立しません。**
>
> 作り方は Claude Code です。IP案件でいちばん開発費を食うのは機能実装ではなく、
> "この口調は違う"への修正を何往復もすることです。
> 私どもはその反映を**即日**でお返しできます。
> これは開発費の話ではなく、**御社の監修担当の方が消耗しない**という話です。」

### クロージング（5分）
> 「事業判断は今日お願いしません。
> **キャラクター1体・3〜4週間のPoC**から始めさせてください。
> 御社の工数は会議3回だけです。実機を見てから、続きをご判断ください。
>
> 御社が27年前に出した答えに、技術がようやく追いつきました。
> **もう一度、御社が最初にやる番だと思っています。**」

## 5. 想定反論への即答（詳細は 04-faq-risks.md）

| 反論 | 一言返し |
|---|---|
| **「そんなにいい話なら、なぜ御社がやらないの？」** | **「IPがないからです。この構想はIPがないと成立しません」**（最重要・必ず聞かれる） |
| 「実績は？」 | 「自社キャラのロウで実装しています。まずそれをご覧ください」 |
| 「エンジンだけ買えばいいのでは？」 | 「**その通りです。それが本日のご提案です**」 |
| 「AIにキャラを演じさせるのは…」 | 「全部は演じさせません。監修済みセリフが主、生成は補完です」 |
| 「Desktop Mate があるのでは」 | 「あれは"いる"アプリです。本件は"育つ"アプリで、レイヤーが違います」 |
| 「社内でもできる」 | 「**ぜひ社内でやってください。**そのための中身と作り方をお持ちしました」 |
| 「うちにリソースがない」 | 「B案（内製化支援型）があります。作ってからお渡しします」 |
| 「誰に相談すれば」 | 「新規事業とデジタル事業の両方に関わる方が理想です。ご紹介いただけますか」 |
